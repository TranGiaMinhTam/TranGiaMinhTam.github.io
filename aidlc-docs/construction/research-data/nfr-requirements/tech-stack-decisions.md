# Technology Stack Decisions - U-04 Research and Data

## Decision Summary

U-04 retains React 19, strict TypeScript, Vite, Vitest, Testing Library, native semantic HTML, passive inline SVG where relationship meaning benefits, and CSS Modules. It adds no runtime dependency, remote client, data service, or deployment component. Pure selectors consume U-01 verified records and evidence contracts, while three immutable bodies enter the active U-02 shell seam after a guarded candidate approval.

## Selected Stack

| Concern | Selection | U-04 rationale and constraint |
| --- | --- | --- |
| Runtime | React 19 function components | Three static view-model compositions need no new state or rendering framework. |
| Language | TypeScript 5.9 strict mode | Closed domain kinds, typed endpoints, immutable view models, and exhaustive failure results. |
| Data selection | Pure U-01 source and evidence selectors | Prevent direct legacy-data reads and former-owner leakage. |
| Relationships | Indexed immutable TypeScript collections | One source for visible tracks and semantic alternatives with linear growth. |
| Markup | Native section content, headings, lists, tables, figures, and anchors | Accessible behavior and degradation without component-library runtime. |
| Visuals | CSS geometry and passive inline SVG only where informative | Custom scientific structures without fabricated charts or charting dependency. |
| Styling | One U-04 CSS Module plus U-01 tokens | Three distinct geometries, one theme system, and bounded CSS. |
| Media | Vite-resolved same-origin manifest assets | Exact allowlist, lazy figures, user-initiated documents, and GitHub Pages compatibility. |
| State | Local optional figure-failure and emphasis state | No canonical data copy, global store, carousel, filter, or hidden disclosure. |
| Shell integration | Existing typed section-body registry | Register exactly three bodies and preserve shell controllers. |
| Testing | Vitest, jsdom, Testing Library, and jest-dom | Semantic queries, deterministic fixtures, image failure, links, and body ownership. |
| Verification | TypeScript, ESLint, Vite manifest, boundary and recovery scripts | Exact budgets, imports, assets, former-owner exclusion, and activation gates. |
| Hosting | Existing GitHub Pages workflow | No infrastructure or runtime-service change. |

No declared dependency version is upgraded. Code Generation must record exact installed versions and prove the lockfile remains unchanged.

## TS-001 - Verified Research Projection

### Decision

Create a lightweight U-04 projection from verified project records and only their six published evidence relationships. Components consume derived immutable view models.

### Constraints

- Molecular docking, cashew testa, and SIM-LSE are assigned through a closed project-ID/domain mapping.
- Required project facts are validated before accepted rendering.
- Contribution disclosure is explicit and closed; it cannot be inferred from methods.
- Former-owner journal and WordPress data is neither imported nor accepted as selector input.
- Findings have stable codes and ordering.

### Rejected Alternatives

- Direct component imports from `src/data/research.ts` bypass the verified model boundary.
- Free-text domain inference could duplicate or misclassify projects.
- Importing `writing` would make former-owner content reachable.

## TS-002 - Indexed Relationship Derivation

### Decision

Use project- and endpoint-keyed maps to build one immutable relationship collection in linear passes. Project structures and semantic rows project from that collection.

### Constraints

- Method, tool, time, and evidence endpoints have stable project-scoped identifiers.
- Duplicate IDs and broken endpoints fail closed.
- Visible and semantic relationship ID sets must match exactly.
- Six-project and 36-relationship fixtures produce deterministic repeated output.
- Components do not filter the full relationship list inside per-project render loops.

## TS-003 - Three Native Compositions

### Decision

Implement three focused React compositions with native DOM and locally owned geometry:

- computational pipeline;
- specimen-to-assay bench;
- analytical signal sheet.

### Constraints

- Core facts remain visible without disclosure controls.
- Each structure has an intentional one-column transformation.
- No shared generic project container dictates identical DOM or geometry.
- Optional emphasis can alter style only.
- No carousel, accordion, masonry, dashboard, or card framework is introduced.

## TS-004 - Semantic Visual Alternative

### Decision

Use captioned ordered lists or tables generated from the normalized relationships as the complete alternative for any informational CSS/SVG relationship view.

### Constraints

- Relationship sets and order are exact across visual and semantic output.
- Meaning remains complete with CSS disabled or SVG unavailable.
- Text marker and relationship kind supplement color.
- Tests query semantic roles and accessible names, not visual class implementation.

## TS-005 - Evidence and Media Strategy

### Decision

Resolve evidence through the U-01 manifest. Render project images as lazy native `img` elements and documents/images as purpose-labeled native anchors.

### Constraints

- The three figures retain accurate alternative text, intrinsic or reserved geometry, lazy loading, and asynchronous decoding.
- The three PDFs are emitted but absent from the initial request inventory.
- No embed, prefetch, preload, runtime fetch, remote CDN, base64 asset, path concatenation, or raw directory reference is allowed.
- Missing optional evidence omits its action only.
- Image failure changes only the figure state.

### Rejected Alternatives

- Embedded documents would initiate more than 11 MB without visitor intent.
- Eager figures would add 1.25 MB below the first viewport.
- Remote image services add privacy, availability, and deployment complexity.

## TS-006 - CSS and Theme Strategy

### Decision

Use a focused U-04 CSS Module with existing semantic tokens, CSS Grid/Flexbox, logical properties, and content-driven media queries.

### Constraints

- Total active CSS remains at or below 30,720 bytes.
- Light and dark modes share one DOM and one rule structure.
- Computational, laboratory, and analytical geometries remain distinct without depending on color.
- Long labels and evidence actions wrap safely.
- Reduced-motion behavior disables optional transitions.
- No global override, routine `!important`, legacy stylesheet, or duplicated mobile tree.

## TS-007 - Minimal Local State

### Decision

React local state is permitted only for individual figure failure and optional relationship emphasis.

### Constraints

- Verified project records and normalized relationships never enter editable component state.
- No context provider, reducer, global store, filter state, pagination, or disclosure state is added.
- Repeat renders from identical props preserve identical content and identifiers.
- Evidence anchors and publication status remain correct without JavaScript enhancement.

## TS-008 - Test and Measurement Strategy

### Automated layers

| Layer | Evidence |
| --- | --- |
| Selection | Exact one-project-per-domain allocation, required fields, contribution disclosures, ordering, and former-owner exclusion |
| Relationships | Unique endpoints, broken/duplicate rejection, exact visual/semantic equality, and repeated-run output |
| Capacity | Six projects and at least 36 relationships using indexed linear derivation |
| Components | Headings, contexts, methods, tools, time, status, figures, evidence names, and local failure |
| Integration | Exactly three U-04 bodies active and five later bodies temporary |
| Security | Safe schemes, same-origin evidence, no raw source, unsafe markup, network API, or external SVG |
| Build | Exact JavaScript, CSS, figure, document, emitted-asset, and initial-request inventories |

### Rendered layers

- Review 320, 768, 1280, and 1440 CSS pixels in light and dark themes.
- Inspect keyboard order, focus, contrast, non-color cues, semantic equivalence, figure failure, reduced motion, zoom, text spacing, and overflow.
- Record a mobile-profile LCP, CLS, and interaction run when tooling is available.
- Classify unavailable browser automation as P1 rather than passing it by inference.
- Require explicit candidate approval before live registration.

## TS-009 - Static Security and Routing Boundary

### Decision

Keep U-04 entirely same-origin and static, with an empty typed future-note destination seam.

### Constraints

- Evidence sources come only from manifest records.
- No current journal destination is published.
- Approved future local destinations use the `#/journal/{slug}` namespace, but U-07 owns parsing and detail rendering.
- React text output and passive SVG avoid unsafe HTML.
- Dependencies and lockfile remain unchanged.

## TS-010 - Candidate and Activation Strategy

### Decision

Build an isolated U-04 candidate that supplies the three new bodies to the active U-03 shell. Keep the live body registration unchanged until all P0 gates and explicit rendered approval pass.

### Constraints

- Candidate output uses a temporary directory and never overwrites deployable `dist/`.
- Preflight records active-entry, shell, identity, dependency, evidence, and recovery hashes.
- Candidate verification enforces the 250,000-byte JavaScript and 30,720-byte CSS limits plus the 12-percent regression gate.
- Activation changes only the approved body-registry composition seam.
- A post-activation P0 failure restores the exact pre-switch content through a recoverable patch.

## Infrastructure, API, and Data Decisions

- No backend, endpoint, database, queue, cache service, authentication, analytics, CMS, remote image service, or runtime secret is introduced.
- Existing GitHub Pages hosting and Vite static asset semantics remain unchanged.
- Infrastructure Design is not required unless a later approved requirement changes deployment architecture.
- U-04 persists no visitor data.

## Extension Compliance

- Security Baseline: disabled and not loaded; the selected stack still enforces the approved same-origin, safe-markup, and no-network requirements.
- Property-Based Testing: disabled and not loaded; deterministic malformed tables, doubled-volume fixtures, and repeat-run checks remain required.
