# NFR Requirements - U-04 Research and Data

## Scope and Acceptance Semantics

These requirements apply to the Computational Projects, Laboratory Research, and Data Stories selectors, view models, relationship projections, evidence actions, figures, semantic alternatives, styles, three-body shell registration, candidate, and active production artifact. A P0 failure blocks U-04 activation or completion. A P1 target requires evidence and an explicit limitation when the local environment cannot execute the relevant browser measurement.

## Scalability and Capacity

### U04-NFR-SCL-001 - Doubled Research Volume

- Pure project selection, domain allocation, endpoint indexing, relationship generation, visual projection, and semantic projection must handle six projects and at least 36 total method, tool, time, and evidence relationships without schema or component changes.
- Processing remains linear in project records plus relationship endpoints. Repeated array scans inside project or relationship loops are prohibited.
- Identifier creation, finding order, relationship order, and accepted view models remain identical across repeated runs with identical input.
- The capacity fixture does not authorize publication of duplicate or synthetic projects; it exists only for algorithmic evidence.

**Acceptance method**: doubled-volume fixtures, keyed endpoint resolution, source inspection, repeated-run equality, and relationship-set equality.

## Performance

### U04-NFR-PER-001 - JavaScript Budget

- All minified JavaScript reachable from the active Vite entry after U-04 activation totals no more than 250,000 bytes.
- Growth from the 223,999-byte U-03 production baseline is no more than 12 percent. Because the absolute limit is stricter, exceeding either condition blocks activation.
- The budget includes U-01 through U-04 selectors, models, three research bodies, semantic alternatives, and eager dependencies.
- No charting, carousel, animation, state-management, media, UI, or remote-content runtime dependency may be added.

**Acceptance method**: Vite manifest traversal, exact byte comparison, dependency and lockfile hashes, and eager-module inspection.

### U04-NFR-PER-002 - CSS Budget

- Active initial CSS totals no more than 30,720 bytes.
- Three locally owned structures share U-01 semantic tokens but do not share one repeated geometry.
- Responsive behavior uses one DOM per domain and content-driven media queries.
- No legacy global stylesheet, generated utility framework, duplicated light/dark tree, or routine `!important` enters the active graph.

**Acceptance method**: emitted CSS bytes, selector inspection, prohibited-pattern checks, and rendered matrix review.

### U04-NFR-PER-003 - Figure Delivery

| Figure | Maximum source bytes |
| --- | ---: |
| Molecular docking | 255,505 |
| Cashew polyphenol | 164,808 |
| Data analytics | 831,243 |

- Figures use published manifest URLs, intrinsic dimensions or reserved aspect-ratio geometry, `loading="lazy"`, and `decoding="async"`.
- None of the three is requested in the identity first viewport.
- A derivative may replace a source only with recorded provenance and an equal-or-smaller byte result.
- Failure affects only the local figure surface.

**Acceptance method**: source and emitted byte inventory, DOM attribute tests, layout-reservation checks, and initial-request classification.

### U04-NFR-PER-004 - Document Delivery

| Document | Exact bytes |

| WICO poster | 7,702,179 |
| SIM-LSE certificate | 51,969 |
| **Total** | **11,244,477** |

- Only these three U-04 documents may be emitted.
- No preload, prefetch, object, embed, iframe, runtime fetch, or automatic viewer request is permitted.
- A document request begins only after activation of its purpose- and type-labeled native evidence link.
- The initial request inventory separates emitted assets from fetched assets.

**Acceptance method**: manifest inventory, HTML/source scan, network inventory where available, and native-action tests.

### U04-NFR-PER-005 - Rendered Performance

- Under a documented representative mobile profile, Largest Contentful Paint targets at most 2.5 seconds and Cumulative Layout Shift at most 0.10.
- Local evidence emphasis and section navigation target a response within 200 milliseconds.
- Runs record browser, version, operating system, viewport, throttling, cache state, sample count, and aggregation.
- If no supported browser runner exists, structural performance safeguards still run and the missing timing is recorded as a P1 limitation, never as a pass.

## Availability and Resilience

### U04-NFR-AVL-001 - Text-First Continuity

These independent failures cannot remove verified question, context, contribution disclosure, methods, tools, time, or semantic relationships:

- one or more optional evidence identifiers do not resolve;
- a figure request or decode fails;
- optional emphasis state is unavailable;
- CSS or SVG interpretation is degraded;
- enhanced shell navigation is unavailable.

Unresolved optional evidence removes only its action. Figure failure produces a local media-unavailable status. No retry loop, remote fallback, blank registered section, or uncaught error is allowed.

## Security and Privacy

### U04-NFR-SEC-001 - Static Publication Boundary

- Evidence targets resolve only from the published manifest and use same-origin build URLs.
- The future note-destination contract accepts only approved `#/journal/{slug}` values; the current U-04 collection is empty.
- Reject `javascript:`, `data:`, arbitrary remote URLs, external SVG references, unsafe HTML, dynamic code execution, raw-source paths, and directory-derived publication.
- U-04 adds no fetch client, analytics, tracking, storage, authentication, form, secret, service worker, or cross-origin request.
- Verified strings render as text through React and native SVG text nodes.
- The disabled Security Baseline extension does not weaken these product-specific P0 controls.

**Acceptance method**: source/import scans, scheme validation, manifest resolution, build inventory, unchanged dependencies, and active boundary checks.

## Reliability and Content Integrity

### U04-NFR-REL-001 - Fail-Closed Required Assembly

Stable ordered blocking findings are required for:

- missing or duplicate computational, laboratory, or data-story project;
- empty question, summary, methods, tools, or time context;
- unsupported project-domain allocation;
- duplicate project or relationship identifier;
- missing project, method, tool, time, or required evidence endpoint.

An accepted selection contains exactly three projects, one per domain, in registry order. Findings never infer role, result, metric, repository, target identity, external writing, or replacement evidence.

### U04-NFR-REL-002 - Visual and Semantic Equivalence

- Every visible method, tool, time, and evidence relationship has exactly one matching semantic relationship identifier.
- Visual and semantic identifier sets and source order are equal, with no duplicate or broken endpoint.
- Emphasis changes style only. Removing styling or SVG interpretation leaves the complete ordered semantic meaning.
- Re-rendering identical input produces identical accessible content.

### U04-NFR-REL-003 - Former-Owner Exclusion

- The existing local journal slug, its content, and all WordPress writing records are excluded from U-04 selection, presentation, destination contracts, and candidate build reachability.
- Data Stories publishes only the verified SIM-LSE project and non-interactive `Research notes are being prepared` status.
- A source boundary test fails if former-owner titles, URLs, biography claims, or journal content enter U-04.

## Maintainability

### U04-NFR-MNT-001 - Automated Quality Gate

Before activation, all of these pass:

- strict TypeScript and unused-code checks;
- ESLint without new warning;
- focused selector, mapping, relationship, component, evidence, failure, and registry tests;
- complete regression suite;
- candidate and production Vite builds;
- exact code, figure, document, and request measurements;
- prohibited-import, former-owner, raw-source, unsafe-pattern, dependency, and ownership boundaries;
- capacity and repeat-run fixtures;
- semantic role, name, heading, ordered-list/table, image, status, and link assertions.

Tests do not depend on hashed class names, decorative DOM depth, screenshots alone, or duplicated factual fixtures presented as an alternate source.

### U04-NFR-MNT-002 - Unit Ownership

- U-04 application source stays inside `src/portfolio/research/` except the smallest approved body-registry integration and verification tooling.
- Components consume immutable presentation view models and cannot import `src/data` or reshape canonical records.
- U-04 registers exactly `computational-projects`, `laboratory-research`, and `data-stories`.
- Identity, Questions, shell controllers, and the five later temporary bodies remain unchanged.
- U-04 cannot import academic, impact, contact, or journal presentation folders.
- A typed empty future-note destination seam is the only U-07-facing interface.

## Usability and Accessibility

### U04-NFR-USE-001 - WCAG 2.2 AA-Oriented Acceptance

Evidence covers:

- logical shell and component heading order;
- visible contribution disclosures, publication status, method/tool labels, and time context;
- native evidence actions with purpose-specific accessible names and visible unobscured focus;
- accurate figure alternative text and local failure status;
- at least 4.5:1 normal-text contrast and 3:1 large-text, focus, control, and meaningful-graphic contrast;
- text labels, sequence, markers, and line styles in addition to color;
- exact semantic alternatives for informational relationships;
- no information gated by hover, focus, motion, pointer, SVG, or figure success;
- usable target sizing and spacing;
- reduced motion, increased text spacing, 200-percent zoom, and 320-pixel reflow in both themes.

### U04-NFR-USE-002 - Responsive Matrix

- Review widths are 320, 768, 1280, and 1440 CSS pixels in light and dark themes.
- The computational pipeline, laboratory bench, and analytical signal sheet retain visibly distinct geometry at wide widths and each becomes one ordered column at narrow widths.
- Long method labels, evidence actions, contribution disclosures, and status text wrap without collision.
- No document-level horizontal overflow, clipped focus, obscured target, hidden relationship, or inaccessible local overflow is permitted.

## Compatibility

### U04-NFR-CMP-001 - Browser Policy

- Target the latest two stable major releases available at verification time for Chrome, Edge, Firefox, and Safari, plus current iOS Safari and Android Chrome.
- Record exact tested browsers and platforms; unavailable targets receive a P1 limitation.
- Native HTML, CSS, and passive SVG provide the functional baseline.
- No browser-specific markup or separate mobile component tree is permitted.

## Structural Uniqueness

### U04-NFR-UNI-001 - Three-Domain Acceptance

The rendered result must contain:

- a computational method pipeline with tool annotations and evidence terminals;
- a specimen-to-assay laboratory bench with an explicit prototype boundary;
- an analytical signal sheet with workflow stages, evidence, and publication status.

Blocking patterns include generic project cards, repeated tile grids, a conventional journal list, invented dashboard charts, carousels, accordion-dependent facts, relabeled copies of one structure, U-03 constellation reuse, or palette-only differentiation.

## Acceptance Evidence

### U04-NFR-EVD-001 - Reproducible Package

The Code Generation plan must capture:

- exact approved file scope, baseline hashes, dependencies, and recovery state;
- focused and complete tests, strict types, lint, candidate and production builds;
- JavaScript/CSS, figure/document, and initial-request inventories;
- required-data failure, optional-evidence failure, relationship equality, former-owner exclusion, and three-body ownership;
- four-width, two-theme review with keyboard, focus, contrast, zoom, text spacing, reduced motion, overflow, and uniqueness observations;
- browser versions, performance profile, warnings, limitations, and user candidate decision;
- guarded activation and post-activation evidence.
