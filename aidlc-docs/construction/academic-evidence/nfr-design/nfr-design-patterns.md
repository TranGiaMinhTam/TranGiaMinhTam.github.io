# NFR Design Patterns - U-05 Academic and Evidence

## Design Objective

U-05 must activate two unique, evidence-grounded bodies without weakening verified academic facts, eagerly requesting 24,117,664 evidence bytes, confusing the transcript with the pending CV, leaking the Identity portrait or former-owner material, or exceeding cumulative budgets. Required academic structure fails closed; optional evidence and preview failures remain local.

## Pattern P-01 - Typed Required and Optional Failure Partition

- A pure assembler validates required programs, facts, explicit status, provenance, identifiers, and relationship endpoints.
- Required failures return a closed rejected result with stable ordered findings.
- Missing optional transcript or scholarship evidence returns non-blocking findings and removes only its marker or action.
- Image failure is local component state and cannot mutate accepted evidence metadata.
- Identical input always produces identical acceptance and findings; deterministic failures are never retried.

Supports U05-NFR-AVL-001, U05-NFR-REL-001, U05-NFR-MNT-001, and U05-NFR-EVD-001.

## Pattern P-02 - Indexed Linear Academic and Evidence Assembly

1. Index academic programs, evidence records, and relationship endpoints once.
2. Validate the closed program and evidence eligibility catalogs.
3. Project academic facts and strata in stable source order.
4. Group accepted evidence in one pass.
5. Derive archive rows, spectrum entries, and semantic counts from the same groups.
6. Verify endpoint, membership, order, and count equivalence.

The path remains linear for four programs, twenty evidence items, and eighty relationships. Components never classify or rescan complete collections while rendering.

Supports U05-NFR-SCL-001, U05-NFR-REL-001/002, and U05-NFR-MNT-001.

## Pattern P-03 - Manifest-Backed Evidence Capabilities

- A pure adapter accepts only a U-05-eligible identifier and published manifest index.
- PDFs become typed text-document capabilities containing metadata and a user-initiated native destination.
- Images become typed lazy-image capabilities containing intrinsic geometry, alternative text, async decode, and local failure metadata.
- Unsupported, unpublished, malformed, portrait, private, raw, former-owner, pending-CV, and later-unit entries produce no capability.
- Components cannot concatenate paths, infer media kinds, or import asset directories.

Supports U05-NFR-PER-003/004, U05-NFR-AVL-001, U05-NFR-SEC-001, and U05-NFR-REL-003.

## Pattern P-04 - Native Deferred Evidence

- Seven PDFs remain metadata-only until a native link is activated.
- Three images use native lazy loading, async decoding, and reserved geometry.
- No iframe, object, embed, preload, prefetch, canvas rasterizer, observer-driven loader, remote transform, service worker, or programmatic request is added.
- Image failure replaces only the preview and retains metadata plus the full-image action.
- Emitted assets and initial requests are measured separately.

Supports U05-NFR-PER-003 through U05-NFR-PER-005 and U05-NFR-AVL-001.

## Pattern P-05 - Closed Publication Allowlist

- A frozen eligibility catalog contains the ten approved U-05 evidence identifiers and their groups.
- Destinations resolve only through same-origin published manifest records.
- Duplicate identifiers, unsafe schemes, raw paths, arbitrary URLs, directory discovery, and non-U-05 records are rejected before view-model creation.
- The transcript remains `transcript`; no selector or label may convert it into a CV.

Supports U05-NFR-SEC-001, U05-NFR-REL-003, and U05-NFR-MNT-002.

## Pattern P-06 - Shared Archive and Semantic Projection

- One immutable ordered group collection owns evidence membership and counts.
- The archive projector creates visible rows from the collection.
- The spectrum projector creates compact group marks from the same collection.
- The semantic projector creates adjacent count entries from the same collection.
- Exact group identifiers, labels, order, item membership, and counts are verified.
- Labels, counts, markers, and borders communicate meaning independently of color or SVG.

Supports U05-NFR-REL-002 and U05-NFR-USE-001/002.

## Pattern P-07 - Behavior Reuse, Geometry Separation

- Shared primitives own evidence actions, text-document previews, lazy-image failure, status labels, and semantic counts.
- Academic Trajectory alone owns curriculum strata, institution anchors, subject/result clusters, recognition, and academic evidence geometry.
- Evidence Library alone owns grouped archival rows, category anchors, previews, and spectrum geometry.
- No generic card-list component or visual-mode prop produces both section structures.

Supports U05-NFR-MNT-002, U05-NFR-USE-002, and U05-NFR-UNI-001.

## Pattern P-08 - Minimal Local State

- Immutable programs, facts, status, evidence, groups, relationships, counts, and ordering remain props.
- Only an individual image preview may own a failure boolean.
- Native category anchors and evidence links require no React state.
- No filter, accordion, carousel, pagination, modal-only metadata, reducer, provider, global store, or persistence is added.

Supports U05-NFR-PER-005, U05-NFR-AVL-001, and U05-NFR-USE-001.

## Pattern P-09 - Headroom-Preserving Native Composition

- Strict TypeScript, native React, semantic HTML, CSS Grid/Flexbox, and bounded passive SVG replace new runtime packages.
- One U-05 CSS Module uses existing semantic tokens and one DOM per section.
- Candidate manifest evaluation enforces 274,000-byte JavaScript, 10-percent growth, and 43,008-byte CSS limits.
- Reserved image geometry and state-free navigation support LCP, CLS, and interaction targets.

Supports U05-NFR-PER-001 through U05-NFR-PER-005 and U05-NFR-MNT-001.

## Pattern P-10 - Immutable Composed Body Registry

- U-05 exports exactly `academic-trajectory` and `evidence-library` factories.
- The existing duplicate-rejecting composer combines them with the approved five-body registry.
- A ten-slot test requires seven finished bodies and three unchanged temporary fallbacks.
- Shell navigation, progress, focus, history, theme, and observation remain unchanged.

Supports U05-NFR-AVL-001, U05-NFR-MNT-002, and U05-NFR-EVD-001.

## Pattern P-11 - Layered Accessibility and Responsive Evidence

1. Pure tests establish exact facts, status, grouping, counts, exclusions, and relationship validity.
2. Semantic tests verify headings, lists, figures, statuses, links, alternatives, and names.
3. Calculated evidence checks text, focus, control, and meaningful-graphic contrast.
4. Failure tests cover optional evidence, image loss, CSS/SVG degradation, and long content.
5. Keyboard, focus, reduced motion, target, zoom, and text-spacing review covers interaction.
6. The 320, 768, 1280, and 1440 CSS-pixel light/dark matrix covers stacking, wrapping, clipping, and overflow.

Supports U05-NFR-AVL-001, U05-NFR-REL-002, U05-NFR-USE-001/002, and U05-NFR-CMP-001.

## Pattern P-12 - Guarded Candidate, Recovery, and Evidence

### Candidate phase

- Capture active-entry, registry, dependency, asset, and recovery baselines.
- Build an isolated seven-body candidate in a temporary output directory.
- Run types, lint, focused/full tests, boundary checks, recovery verification, capacity, failure, exclusions, equivalence, ownership, budgets, and request classification.
- Any P0 failure leaves the live registry unchanged.

### Rendered review and activation

- Review eight width/theme states, keyboard and focus, image failure, reduced motion, text spacing, zoom, long provenance, action wrapping, overflow, semantic counts, and structural uniqueness.
- Record browser performance when available and classify unavailable P1 evidence honestly.
- Require explicit candidate approval, capture exact pre-switch registration, and change only the registry composition seam.
- Restore the recorded registration through a recoverable patch if post-activation P0 acceptance fails.

Supports every U-05 NFR, especially U05-NFR-MNT-001/002, U05-NFR-UNI-001, and U05-NFR-EVD-001.

## Static Observability and Infrastructure Decision

Runtime queues, caches, circuit breakers, workers, monitoring agents, remote logging, APIs, databases, document processors, remote image services, and retry subsystems are not applicable. Observability consists of typed findings, automated results, boundary reports, manifest measurements, request classifications, rendered-review evidence, user decisions, and recovery hashes. Development-only collectors never enter the browser bundle.
