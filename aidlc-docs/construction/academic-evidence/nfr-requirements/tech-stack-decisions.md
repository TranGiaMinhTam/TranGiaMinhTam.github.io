# Technology Stack Decisions - U-05 Academic and Evidence

## Decision Summary

U-05 retains React 19, strict TypeScript, Vite, Vitest, Testing Library, native semantic HTML, optional passive inline SVG, and CSS Modules. It adds no runtime dependency, PDF viewer, image service, remote client, backend, or deployment component. Pure selectors project verified records and the publication manifest into two immutable view models before guarded shell registration.

## Selected Stack

| Concern | Selection | Constraint |
| --- | --- | --- |
| Runtime | React 19 function components | Static view-model rendering and local image-failure state only |
| Language | TypeScript 5.9 strict mode | Closed academic, evidence, grouping, relationship, and finding types |
| Selection | Pure verified-source and manifest selectors | No legacy data or asset-directory import in components |
| Indexing | Immutable maps and ordered arrays | Linear assembly and deterministic doubled-volume behavior |
| Markup | Native headings, lists, figures, anchors, and status text | Keyboard and semantic baseline without widget runtime |
| Visuals | CSS geometry and passive inline SVG when useful | Count summaries only; no fabricated chart data |
| Styling | One U-05 CSS Module plus existing tokens | Two distinct geometries within the 43,008-byte ceiling |
| Documents | Text-first metadata plus native anchors | No viewer, rasterizer, embed, preload, or runtime fetch |
| Images | Native lazy `img` elements | Intrinsic geometry, async decode, alternatives, local failure |
| State | Local image-failure state only | No filter, carousel, disclosure, pagination, or global store |
| Integration | Existing duplicate-rejecting body registry | Exactly two new body keys after candidate approval |
| Testing | Vitest, jsdom, Testing Library, jest-dom | Semantic assertions, capacity, failures, actions, ownership |
| Verification | TypeScript, ESLint, Vite manifest, boundary and recovery scripts | Exact budgets, assets, requests, exclusions, activation |
| Hosting | Existing GitHub Pages workflow | No infrastructure or routing change |

No dependency version is upgraded. Code Generation must record installed versions and prove that dependency declarations and the lockfile remain unchanged.

## TS-001 - Verified Academic Projection

Create an explicit U-05 projection from verified `academic-item` records. A closed reviewed mapping classifies exact facts and current status; arbitrary runtime prose parsing is prohibited. Missing required programs or facts produce stable findings. Components receive accepted immutable strata only.

Rejected alternatives are direct component imports from legacy education data, date inference from free text, and presentation-time grade parsing.

## TS-002 - Published Evidence Projection

Select the ten U-05-eligible records through stable identifiers and manifest metadata. Index records once, reject duplicate or unsafe identifiers, group them through closed rules, and derive rows plus counts from the accepted collection. The portrait and non-U-05 records are excluded before view-model creation.

## TS-003 - Native Curriculum Cross-Section

Implement Academic Trajectory with semantic HTML and locally owned CSS Grid/Flexbox geometry. One DOM supports wide learning strata and narrow continuous reading order. Status, institution, period, subjects, results, recognition, and evidence remain visible without a timeline package or custom interaction state.

## TS-004 - Native Archival Index

Implement Evidence Library as semantic grouped sections and asymmetric rows. Optional native category links target stable group anchors. No filtering, carousel, masonry, card framework, or modal-only metadata is introduced.

## TS-005 - Document and Image Strategy

- PDFs render as metadata-only previews and native on-demand links.
- Images render through lazy, async-decoded, intrinsically sized native elements.
- Full assets use Vite-resolved same-origin manifest URLs.
- Preview failure changes only local state.
- No PDF.js, canvas rasterization, iframe, object, embed, remote thumbnail service, base64 copy, or runtime network client is allowed.

## TS-006 - Semantic Evidence Spectrum

Build spectrum entries from accepted archive groups, then project both compact visual marks and an adjacent semantic count list. Identifiers, labels, counts, and order are identical. CSS or passive SVG can express geometry, while labels, counts, borders, and markers preserve non-color meaning.

## TS-007 - CSS and Theme Strategy

Use one locally owned U-05 CSS Module with existing semantic tokens, logical properties, content-driven media queries, visible focus, and reduced-motion handling. Both themes share one DOM and rule structure. No global override, duplicated mobile tree, legacy stylesheet, or routine `!important` is allowed.

## TS-008 - Test and Measurement Strategy

| Layer | Evidence |
| --- | --- |
| Academic selection | Exact programs, facts, status, ordering, provenance, and malformed-record findings |
| Evidence selection | Exact ten-record allowlist, grouping, duplicates, unsafe records, and exclusions |
| Relationships | Valid endpoints, canonical transcript/scholarship reuse, stable order |
| Equivalence | Archive, spectrum, and semantic identifiers/counts match exactly |
| Capacity | Four programs, twenty items, eighty relationships, linear indexed assembly |
| Components | Headings, facts, status, metadata, link names, lazy images, local failure |
| Integration | Exactly two U-05 bodies added; three later bodies remain temporary |
| Security | No unsafe scheme, raw/private path, runtime request, portrait, false CV, or former-owner content |
| Build | Exact JavaScript, CSS, PDF, image, emitted-asset, and initial-request inventories |

Rendered review covers four widths, two themes, keyboard order, focus, contrast, non-color cues, count equivalence, image failure, reduced motion, zoom, text spacing, long provenance, action wrapping, and overflow. Browser timing is recorded when available and otherwise classified P1.

## TS-009 - Candidate and Activation Strategy

Build an isolated U-05 candidate by composing the approved U-01 through U-04 bodies with the two U-05 bodies. Keep the live registration unchanged until strict P0 gates and explicit rendered-candidate approval pass. Candidate output uses a temporary directory, activation touches only the registry composition seam, and post-activation P0 failure restores the exact pre-switch registration through a recoverable patch.

## Infrastructure, API, and Data Decisions

- No backend, endpoint, database, queue, cache, authentication, analytics, CMS, remote image service, document processor, runtime secret, or infrastructure change is introduced.
- GitHub Pages and Vite static asset semantics remain unchanged.
- Infrastructure Design is unnecessary unless a later approved requirement changes deployment architecture.
- U-05 persists no visitor data.

## Extension Compliance

- Security Baseline is disabled and not loaded; same-origin, safe-markup, no-network, and publication-boundary controls remain mandatory.
- Property-Based Testing is disabled and not loaded; deterministic malformed tables, doubled-volume fixtures, and repeat-run checks remain mandatory.
